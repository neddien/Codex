* Overview

Codex is a cross-platform 2D game engine with an integrated editor. The engine
is written in C++20 and includes:

- ECS-based scene management
- OpenGL rendering and a batched 2D sprite renderer
- Box2D physics
- FMOD Studio audio
- C++ native behaviours and reflection/code generation
- JSON and binary archives
- Virtual filesystems and compressed asset packages
- An ImGui editor with a scene hierarchy, property inspector, profiler, and
  content browser

CMake presets are provided for Linux and Windows. The editor is under active
development.

* Getting started

** Prerequisites

| Tool         | Version                                   |
|--------------+-------------------------------------------|
| Python       | 3.10 or newer                             |
| Conan        | 2.x                                       |
| CMake        | 3.24 or newer; 4.2 or newer for VS 2026   |
| Ninja        | Any recent version                        |
| C++ compiler | GCC or Clang on Linux; MSVC or clang-cl on Windows, all with C++20 |
| Git          | Any recent version                        |

See [[*Platform notes][Platform notes]] for the packages to install on each platform.

FMOD Studio API 2.03.15 is included under ~codex/vendor/fmod~. Its license and
redistribution terms apply.

** Clone

#+begin_src bash
git clone --recurse-submodules <repository-url>
#+end_src

In an existing clone without submodules, run ~git submodule update --init~.

** Install Conan

Install Conan either globally or in a virtual environment.

Globally:

#+begin_src bash
pip install conan
#+end_src

In a virtual environment (activate it again in every new shell):

#+begin_src bash
python3 -m venv .venv            # Windows: py -3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install conan
#+end_src

* Building

** build.py

~scripts/build.py~ configures, builds, installs, and runs the engine with one
command. The first build of a preset also downloads or builds its
dependencies, which takes a while.

#+begin_src bash
# Build Debug with the default preset.
python scripts/build.py

# Build, install, and launch CodexEditor.
python scripts/build.py --run

# Build and install Release for a specific preset.
python scripts/build.py --preset linux-gcc --config release --install

# List this host's presets; * marks the default.
python scripts/build.py --list
#+end_src

| Option                 | Effect                                                              |
|------------------------+---------------------------------------------------------------------|
| ~--list~               | List this host's presets and what is configured and installed       |
| ~--preset NAME~        | Preset to use                                                       |
| ~--config CONFIG~      | ~Debug~ (default), ~Release~, or ~Shipping~                         |
| ~--configure~          | Configure again, e.g. after editing ~CMakePresets.json~             |
| ~--fresh~              | Configure from scratch                                              |
| ~--clean~              | Clean the configuration before building                             |
| ~-t~, ~--target NAME~  | Build only this target (repeatable)                                 |
| ~-j~, ~--jobs N~       | Parallel jobs (default: number of CPUs); ~--no-parallel~ uses one   |
| ~--install~            | Install the configuration after building                            |
| ~--run [PROGRAM]~      | Install, then launch an installed program (default: ~CodexEditor~)  |
| ~--vglrun~             | Launch through VirtualGL's ~vglrun~ (Linux); implies ~--run~        |
| ~--no-launch-json~     | Don't update ~.vscode/launch.json~ after installing                 |
| ~--no-out~             | Hide build output unless a step fails                               |

Arguments after ~--~ are passed to the program started by ~--run~. Without
~--preset~, the most recently configured preset is used, otherwise
~windows-vs2022~ on Windows and ~linux-gcc~ on Linux. ~python scripts/build.py -h~
shows all options.

** Direct CMake workflow

Choose the configuration when building and installing:

#+begin_src bash
cmake --preset linux-gcc
cmake --build builds/linux-gcc --config Debug --parallel
cmake --install builds/linux-gcc --config Debug
#+end_src

To also build TestWork, configure with ~-DCX_ENABLE_TESTWORK=ON~.

** Install layout

| Path                         | Contents         |
|------------------------------+------------------|
| ~installs/<preset>/debug/~   | Debug install    |
| ~installs/<preset>/release/~ | Release install  |
| ~installs/<preset>/~         | Shipping install |

The executables are in each install's ~bin/~, for example
~installs/windows-vs2022/debug/bin/CodexEditor.exe~. Ninja builds also copy
~compile_commands.json~ to the repository root for clangd and other language
servers.

* Running and debugging

Always run the editor from its install, not from the build tree:
~python scripts/build.py --run~ builds, installs, and launches it.

- *VS Code:* ~--install~ adds a launch entry for each installed configuration
  to ~.vscode/launch.json~ (CodeLLDB extension). Your own entries are kept.
- *Visual Studio:* open ~builds/windows-vs2022/Codex.sln~ (or
  ~builds/windows-vs2026/Codex.slnx~) after building that preset once. F5
  builds, installs, and debugs the installed editor.

* Platform notes

** Linux

Install the build tools plus the OpenGL, X11, and GTK 3 development packages:

#+begin_src bash
# Ubuntu/Debian
sudo apt install build-essential clang cmake ninja-build git python3 \
  pkg-config libgtk-3-dev libgl1-mesa-dev libx11-dev libxext-dev libxrandr-dev \
  libxi-dev libxcursor-dev libxinerama-dev libxfixes-dev

# Fedora
sudo dnf install gcc-c++ clang cmake ninja-build git python3 pkgconf-pkg-config \
  gtk3-devel mesa-libGL-devel libX11-devel libXext-devel libXrandr-devel \
  libXi-devel libXcursor-devel libXinerama-devel libXfixes-devel

# Arch Linux
sudo pacman -S --needed base-devel clang cmake ninja git python pkgconf gtk3 \
  mesa libx11 libxext libxrandr libxi libxcursor libxinerama libxfixes
#+end_src

~XDG_SESSION_TYPE~ must be set (~x11~ or ~wayland~); desktop sessions set it
already. Wayland builds may also need the Wayland, xkbcommon, and libdecor
development packages.

** Windows

Install Visual Studio 2022 or 2026 with the *Desktop development with C++*
workload, plus Python, CMake, Git, and Ninja. Install LLVM for ~windows-llvm~.

~build.py~ works from any terminal. When calling ~cmake~ directly with
~windows-msvc~, use a *Developer PowerShell for VS*.

** macOS

As of now there's no intention to continue the support for macOS (this is because I don't own an Apple machine).
